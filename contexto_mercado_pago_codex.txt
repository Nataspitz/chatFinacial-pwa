CONTEXTO PARA CODEX - INTEGRAÇÃO MERCADO PAGO ASSINATURAS

Objetivo do projeto
===================

Implementar cobrança recorrente mensal via Mercado Pago em um sistema/SaaS próprio.

Cenário comercial:
- O dono do sistema também é o vendedor.
- Não haverá marketplace.
- Não haverá comissão para terceiros.
- Todo pagamento deve cair na conta Mercado Pago do dono do sistema.
- A conta que recebe é a conta dona do ACCESS TOKEN usado no backend.
- O fluxo inicial será com credenciais de TESTE.
- Depois, em produção, trocar apenas as variáveis de ambiente para as credenciais de produção.

IMPORTANTE SOBRE SEGURANÇA
==========================

Nunca colocar o Access Token no front-end.
Nunca usar NEXT_PUBLIC_ no Access Token.
Nunca salvar Access Token no repositório.
Nunca enviar Access Token para o navegador.
Nunca commitar .env.local.

Correto:
MERCADO_PAGO_ACCESS_TOKEN=TEST-...
NEXT_PUBLIC_MERCADO_PAGO_PUBLIC_KEY=TEST-...

Errado:
NEXT_PUBLIC_MERCADO_PAGO_ACCESS_TOKEN=TEST-...

A Public Key pode ser exposta no front se for necessário usar Brick/formulário de cartão.
O Access Token só pode existir no servidor/backend.

Arquitetura esperada
====================

Fluxo principal:

1. Usuário logado clica em "Assinar".
2. Front chama uma rota interna do backend:
   POST /api/billing/create-subscription
3. Backend identifica o usuário logado.
4. Backend busca o plano no banco, não confia em preço vindo do front.
5. Backend chama a API do Mercado Pago usando MERCADO_PAGO_ACCESS_TOKEN.
6. Mercado Pago cria uma assinatura/preapproval e retorna init_point ou sandbox_init_point.
7. Backend salva a assinatura no Supabase com status "pending".
8. Front redireciona o usuário para o checkout do Mercado Pago.
9. Mercado Pago confirma via redirect e/ou webhook.
10. Sistema só libera acesso quando a assinatura estiver com status "authorized".

Regra:
- Front decide interface.
- Backend decide plano, preço, usuário, status e liberação de acesso.
- O status salvo no banco é a fonte usada pelo sistema para liberar ou bloquear acesso.

Endpoints principais do Mercado Pago
====================================

Criar assinatura:
POST https://api.mercadopago.com/preapproval

Consultar assinatura:
GET https://api.mercadopago.com/preapproval/{id}

Atualizar/cancelar assinatura:
PUT https://api.mercadopago.com/preapproval/{id}

Listar cobranças/faturas autorizadas:
GET https://api.mercadopago.com/authorized_payments/search

Consultar cobrança/fatura específica:
GET https://api.mercadopago.com/authorized_payments/{id}

Headers obrigatórios no backend
===============================

Authorization: Bearer ${MERCADO_PAGO_ACCESS_TOKEN}
Content-Type: application/json

Payload básico para criar assinatura sem plano associado
========================================================

Usar este fluxo no MVP, porque é mais simples.

{
  "reason": "Assinatura Plano Inicial",
  "external_reference": "USER_ID_INTERNO",
  "payer_email": "email-do-usuario@dominio.com",
  "back_url": "http://localhost:3000/billing/success",
  "status": "pending",
  "auto_recurring": {
    "frequency": 1,
    "frequency_type": "months",
    "transaction_amount": 59.9,
    "currency_id": "BRL"
  }
}

Campos importantes:
- reason: nome/descrição da assinatura.
- external_reference: ID interno do usuário ou assinatura no sistema.
- payer_email: e-mail do usuário pagador.
- back_url: URL para onde o Mercado Pago redireciona após o checkout.
- status: para checkout redirecionado, usar "pending".
- auto_recurring.frequency: 1.
- auto_recurring.frequency_type: "months".
- auto_recurring.transaction_amount: valor mensal.
- auto_recurring.currency_id: "BRL".

Resposta esperada ao criar assinatura
=====================================

O Mercado Pago deve retornar algo parecido com:

{
  "id": "ID_DA_ASSINATURA",
  "status": "pending",
  "init_point": "URL_CHECKOUT_PRODUCAO",
  "sandbox_init_point": "URL_CHECKOUT_TESTE"
}

Para teste:
- Usar sandbox_init_point se vier disponível.
- Se não vier, usar init_point conforme retorno.

Banco de dados mínimo no Supabase
=================================

Tabela plans:

create table plans (
  id uuid primary key default gen_random_uuid(),
  name text not null,
  description text,
  price numeric(10,2) not null,
  currency text not null default 'BRL',
  interval text not null default 'months',
  interval_count int not null default 1,
  is_active boolean not null default true,
  created_at timestamptz not null default now()
);

Tabela subscriptions:

create table subscriptions (
  id uuid primary key default gen_random_uuid(),
  user_id uuid not null,
  plan_id uuid references plans(id),
  mercado_pago_preapproval_id text unique,
  payer_email text not null,
  status text not null default 'pending',
  init_point text,
  sandbox_init_point text,
  raw_payload jsonb,
  current_period_start timestamptz,
  current_period_end timestamptz,
  next_payment_date timestamptz,
  canceled_at timestamptz,
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now()
);

Tabela subscription_invoices:

create table subscription_invoices (
  id uuid primary key default gen_random_uuid(),
  subscription_id uuid references subscriptions(id),
  user_id uuid not null,
  mercado_pago_authorized_payment_id text unique,
  mercado_pago_payment_id text,
  status text not null,
  amount numeric(10,2),
  currency text default 'BRL',
  debit_date timestamptz,
  paid_at timestamptz,
  raw_payload jsonb,
  created_at timestamptz not null default now()
);

Implementação sugerida - criar assinatura
=========================================

Arquivo sugerido em Next.js App Router:
src/app/api/billing/create-subscription/route.ts

Versão inicial para teste manual:

import { NextResponse } from "next/server";

type CreateSubscriptionBody = {
  payerEmail: string;
};

export async function POST(request: Request) {
  try {
    const token = process.env.MERCADO_PAGO_ACCESS_TOKEN;
    const appUrl = process.env.APP_URL ?? "http://localhost:3000";

    if (!token) {
      return NextResponse.json(
        { error: "MERCADO_PAGO_ACCESS_TOKEN não configurado" },
        { status: 500 }
      );
    }

    const body = (await request.json()) as CreateSubscriptionBody;

    if (!body.payerEmail) {
      return NextResponse.json(
        { error: "payerEmail é obrigatório" },
        { status: 400 }
      );
    }

    const response = await fetch("https://api.mercadopago.com/preapproval", {
      method: "POST",
      headers: {
        Authorization: `Bearer ${token}`,
        "Content-Type": "application/json"
      },
      body: JSON.stringify({
        reason: "Assinatura Plano Teste",
        external_reference: `user_test_${Date.now()}`,
        payer_email: body.payerEmail,
        back_url: `${appUrl}/billing/success`,
        status: "pending",
        auto_recurring: {
          frequency: 1,
          frequency_type: "months",
          transaction_amount: 59.9,
          currency_id: "BRL"
        }
      })
    });

    const data = await response.json();

    if (!response.ok) {
      return NextResponse.json(
        {
          error: "Erro ao criar assinatura no Mercado Pago",
          details: data
        },
        { status: response.status }
      );
    }

    return NextResponse.json({
      id: data.id,
      status: data.status,
      init_point: data.init_point,
      sandbox_init_point: data.sandbox_init_point,
      raw: data
    });
  } catch (error) {
    return NextResponse.json(
      {
        error: "Erro inesperado ao criar assinatura",
        details: error instanceof Error ? error.message : String(error)
      },
      { status: 500 }
    );
  }
}

Depois adaptar para usuário real logado
=======================================

A versão acima aceita payerEmail no body apenas para teste.

Na versão real:
- Não receber payerEmail do front.
- Pegar usuário logado pelo Supabase Auth.
- Usar user.id no external_reference.
- Usar user.email no payer_email.
- Buscar planId no banco.
- Buscar preço no banco.
- Nunca aceitar preço vindo do front.
- Salvar a assinatura criada na tabela subscriptions.

Pseudofluxo real:

1. Validar usuário autenticado.
2. Buscar plano ativo no banco.
3. Verificar se usuário já tem assinatura authorized ou pending.
4. Criar assinatura no Mercado Pago.
5. Salvar retorno em subscriptions.
6. Retornar checkoutUrl ao front.

Exemplo de retorno interno para o front:

{
  "checkoutUrl": "sandbox_init_point_ou_init_point",
  "subscriptionId": "id_interno_da_subscription"
}

Botão do front
==============

Exemplo simples:

"use client";

import { useState } from "react";

export function SubscribeButton() {
  const [loading, setLoading] = useState(false);

  async function handleSubscribe() {
    setLoading(true);

    try {
      const response = await fetch("/api/billing/create-subscription", {
        method: "POST",
        headers: {
          "Content-Type": "application/json"
        },
        body: JSON.stringify({
          payerEmail: "test_user_123@testuser.com"
        })
      });

      const data = await response.json();

      if (!response.ok) {
        console.error(data);
        alert("Erro ao criar assinatura");
        return;
      }

      const checkoutUrl = data.sandbox_init_point || data.init_point || data.checkoutUrl;

      if (!checkoutUrl) {
        console.error(data);
        alert("Mercado Pago não retornou URL de checkout");
        return;
      }

      window.location.href = checkoutUrl;
    } finally {
      setLoading(false);
    }
  }

  return (
    <button onClick={handleSubscribe} disabled={loading}>
      {loading ? "Gerando assinatura..." : "Assinar plano teste"}
    </button>
  );
}

Status internos recomendados
============================

pending:
- Assinatura criada, usuário ainda não concluiu checkout.

authorized:
- Assinatura ativa. Usuário pode acessar o sistema.

paused:
- Assinatura pausada. Acesso deve ser bloqueado ou limitado.

cancelled:
- Assinatura cancelada.

payment_failed:
- Cobrança falhou.

expired:
- Assinatura expirada ou inválida.

Regra de acesso
===============

O sistema deve liberar acesso apenas se existir subscription do usuário com:

status = 'authorized'

Exemplo SQL:

select *
from subscriptions
where user_id = auth.uid()
and status = 'authorized'
limit 1;

Não liberar acesso apenas porque o usuário voltou para /billing/success.
Redirect não é confirmação confiável.
Webhook/consulta na API é o que confirma.

Webhook
=======

Endpoint esperado:
POST /api/webhooks/mercado-pago

Lógica:
1. Receber evento do Mercado Pago.
2. Identificar tipo do evento.
3. Pegar o ID do recurso enviado no evento.
4. Consultar a API do Mercado Pago para buscar dados reais.
5. Atualizar banco.
6. Responder 200 rapidamente.

Eventos importantes:
- subscription_preapproval: atualização da assinatura.
- evento de authorized payment/fatura: atualização de cobrança recorrente.
- payment: pagamento aprovado/rejeitado, se usado no fluxo.

Ao receber subscription_preapproval:
- Buscar GET /preapproval/{id}
- Atualizar subscriptions.status

Ao receber authorized payment:
- Buscar GET /authorized_payments/{id}
- Salvar/atualizar subscription_invoices

Cancelar assinatura
===================

Rota interna:
POST /api/billing/cancel-subscription

Backend:
1. Identifica usuário logado.
2. Busca assinatura ativa dele.
3. Chama Mercado Pago:

PUT https://api.mercadopago.com/preapproval/{id}

Body:

{
  "status": "cancelled"
}

4. Atualiza subscriptions:
- status = 'cancelled'
- canceled_at = now()
- updated_at = now()

Atenção:
- Alguns exemplos/documentações usam "cancelled" e outros usam "canceled".
- Implementar o sistema interno aceitando ambos se vierem da API.
- Ao enviar para API, validar no retorno real qual valor foi aceito.

Listar faturas/cobranças
========================

Rota interna:
GET /api/billing/invoices

Backend:
1. Identifica usuário logado.
2. Busca subscription do usuário.
3. Chama:

GET https://api.mercadopago.com/authorized_payments/search?preapproval_id={mercado_pago_preapproval_id}

4. Salva/retorna histórico.

O front deve exibir:
- status
- valor
- data de cobrança/debit_date
- id do pagamento se existir
- se foi aprovado ou falhou

Critérios de aceite
===================

A integração inicial estará correta quando:

1. O Access Token estiver somente no backend.
2. A rota /api/mercadopago/test confirmar que o token carrega sem revelar o token completo.
3. A rota /api/billing/create-subscription criar uma assinatura de teste.
4. A resposta retornar sandbox_init_point ou init_point.
5. O front redirecionar para o checkout.
6. O banco salvar a assinatura como pending.
7. O sistema só liberar acesso quando status for authorized.
8. O webhook ou consulta na API sincronizar status.
9. O usuário conseguir cancelar a assinatura pelo sistema.
10. As faturas/cobranças ficarem registradas ou consultáveis.

Resumo para o Codex
===================

Você deve implementar uma integração de assinatura recorrente mensal com Mercado Pago para um SaaS próprio, sem marketplace. O dono do sistema é o vendedor. O dinheiro cai na conta Mercado Pago dona do Access Token. O Access Token deve ficar apenas no servidor. O MVP deve criar assinatura via POST /preapproval com status pending e auto_recurring mensal. O front apenas chama rota interna e redireciona para sandbox_init_point/init_point. O Supabase armazena planos, assinaturas e faturas. O sistema libera acesso apenas com status authorized.
